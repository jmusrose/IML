# FGM Masking and Frozen-Probe Pipeline Design

## Goal

Create a self-contained `FGM_masking_probe` package that trains and compares No-FGM and FGM models on CREMA-D, Kinetics-Sounds, and AVE, then runs two post-training experiments:

1. Feature-level modality masking to measure which modalities the fusion classifier actually uses.
2. Newly initialized frozen-encoder linear probes to measure the quality of each unimodal representation.

This implementation uses one seed per run. It does not calculate multi-seed mean or standard deviation.

## Isolation Boundary

The new package is a complete copy of the relevant AV_v4 implementation, not a wrapper around `AV_v4`.

It contains local copies of:

- audio-visual models and feature pooling;
- CREMA-D, Kinetics-Sounds, and AVE datasets and transforms;
- shared and dataset-specific training code;
- CMI-FGM state and gradient hooks.

All imports inside the new package are package-relative. Runtime code must not import `AV_v4` or the root-level `cmi_fgm.py`. Generated bytecode, old run outputs, and unrelated scripts are not copied.

## Fair Comparison

For each dataset, the pipeline trains one No-FGM model and one FGM model. The two methods use the same:

- model initialization seed;
- dataset split and sample order;
- data augmentation;
- optimizer and scheduler;
- fusion loss;
- audio and visual auxiliary-probe losses and weights;
- epoch count and all other hyperparameters.

The only method difference is whether CMI-FGM gradient modulation is enabled. No-FGM therefore retains the same unimodal auxiliary objectives as FGM.

## Command-Line Interface

The primary entry point is:

```powershell
python -m FGM_masking_probe.run --dataset ave
python -m FGM_masking_probe.run --dataset cremad
python -m FGM_masking_probe.run --dataset ks
python -m FGM_masking_probe.run --dataset all
```

The command performs training, checkpoint selection, masking evaluation, frozen-probe training, aggregation, and reporting. Dataset-specific hyperparameters default to the copied AV_v4 settings. Probe defaults are 30 epochs with Adam and learning rate `1e-3`, and are exposed as CLI options.

## Training and Checkpoints

Each method writes to an isolated run directory and saves the model with the highest validation accuracy as `best.pt`. The checkpoint contains at least:

- model state dictionary;
- selected epoch and validation metrics;
- complete resolved configuration;
- dataset and method identifiers.

After training, every analysis reloads `best.pt`; analyses do not rely on an in-memory model left by the training loop.

## Experiment A: Feature-Level Masking

For each test batch, the evaluator obtains pooled 512-dimensional audio and visual features using the copied model's feature-extraction methods. It evaluates the fusion classifier under:

- `full`: both real features;
- `mask_audio`: audio replaced, visual retained;
- `mask_visual`: visual replaced, audio retained.

The evaluator runs both required replacement policies:

- `zero`: replace the selected feature with zeros;
- `train_mean`: replace it with that model's corresponding mean training feature.

Training means are computed separately for each trained model using deterministic evaluation preprocessing. Reported values include the three accuracies, both accuracy drops, and masking asymmetry:

```text
drop_audio = full - mask_audio
drop_visual = full - mask_visual
asymmetry = abs(drop_audio - drop_visual)
```

The baseline's larger drop determines the dominant modality. The other modality is labelled weak. No modality is predetermined by dataset name.

## Experiment B: Frozen Linear Probes

For every best checkpoint and modality:

1. Put the corresponding encoder in evaluation mode.
2. Extract and cache pooled training and test features under `torch.no_grad()` using deterministic evaluation preprocessing.
3. Initialize a new `nn.Linear(512, num_classes)` head. Never reuse the auxiliary probe trained with the main model.
4. Train only this head on cached training features.
5. Evaluate test accuracy on cached test features.

Baseline and FGM probes use the same probe seed, initialization procedure, optimizer, learning rate, epoch count, batch size, and feature preprocessing. The encoder state and cached features are never updated by probe training.

## Outputs

Each top-level run writes:

- resolved configuration JSON;
- No-FGM and FGM best checkpoints and training histories;
- raw masking and probe results as JSON;
- tabular results as CSV;
- grouped masking plots as PNG and PDF;
- a concise Markdown report containing dominant/weak-modality identification and empirical acceptance checks.

For `--dataset all`, the masking figure has one subplot per dataset with a shared accuracy axis. A single-dataset run produces one subplot without empty panels.

## Empirical Checks and Failure Semantics

The report evaluates, but does not force, the following directions:

- baseline masking is asymmetric;
- FGM asymmetry is smaller than baseline asymmetry;
- both FGM masked accuracies are below FGM full accuracy;
- FGM full accuracy is at least the baseline full accuracy;
- the FGM weak-modality frozen-probe accuracy exceeds the baseline value;
- zero and train-mean masking lead to the same qualitative conclusion.

Failure to observe one of these directions is an empirical result, not a program error. It is reported explicitly and the process exits successfully. Missing data, incompatible checkpoints, invalid tensor shapes, non-finite losses, or empty splits are program errors and fail with actionable messages.

## Testing and Verification

Focused tests use small synthetic tensors, fake encoders, and tiny data loaders. They verify:

- the copied package has no runtime import dependency on `AV_v4`;
- No-FGM and FGM configurations differ only in the FGM switch;
- best-checkpoint selection and reload;
- zero and mean feature masking formulas;
- masking drops, asymmetry, and baseline-driven weak-modality identification;
- frozen encoders receive no gradients or parameter updates;
- probe heads are newly initialized and train independently;
- JSON/CSV/report schemas and single/all-dataset plotting;
- empirical check failures are reported without becoming process failures.

Verification runs in the repository's `pytorch2.5` environment and includes the focused test suite, package compilation, and a CPU smoke test that exercises the analysis flow without real-dataset training.

## Explicit Non-Goals

- No MOSI or MOSEI extension in this implementation.
- No three-seed orchestration or mean/std aggregation.
- No additional SOTA baselines.
- No raw-input masking.
- No hyperparameter search for FGM or probes.
- No refactor of the existing `AV_v4` package.
